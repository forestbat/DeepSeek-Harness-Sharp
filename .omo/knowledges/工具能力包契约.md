# 工具能力包契约

工具实现由 `Dsh.Tools.Fs`、`Dsh.Tools.Search`、`Dsh.Tools.Shell`、`Dsh.Tools.Plan` 四个能力工程分发，独立叶插件及配置迁移表见 README「工具能力包迁移」。
能力工程不互相引用；Fs 的 worktree 和 Shell/Jobs 按既有服务依赖使用 Core 的 SubprocessService。
持久 shell 随 Shell 分发，实现命名空间为 `Dsh.Tools`，Jobs 只保留 job 服务和工具。

配置 schema 生成器按程序集首个 Plugin ID 汇总配置类型，不代表每个叶插件的运行参数绑定。
判断有效参数必须读 Plugin 注册实现；一次性 shell 和 Search 的既有注册没有消费各自标注的插件配置参数。
旧插件 ID 即使为 false/null 或与新 ID 混用也会明确拒绝，不提供兼容别名。

完整默认宿主的跨域激活顺序在原始提交也不恒定，不能把单次完整目录捕获当作任意启动全局全序契约。
工具拆包的确定性回归通过真实 PluginHost/Composition 加载能力包并比较完整 14 项目录；默认宿主另外检查完整名称集。
真实改前/改后捕获、原始时序复现、精确命令与平台缺口见 `plans/工具拆包交付证据.json` 和 `plans/工具拆包实施记录.md`。

缺少 pwsh 时，五个既有 ToolsTests.Pwsh 测试提前返回；runner 的 pass 不能证明执行过 PowerShell。
